# 사용자 실사용 피드백 (2026-08-02, 두 번째 라운드) — 처리 완료 기록

사용자가 실제로 webmanager를 써보고 준 피드백 일괄. 이 문서는 각 항목의 처리
결과를 기록해서 **다른 에이전트/세션이 같은 걸 다시 조사/구현하지 않게** 하는
목적 — **이 라운드에 디스패치된 작업은 전부 완료됨**(아래 각 항목 상태 참고).
상태값: `구현 완료` / `계획만`(문서만, 구현 안 함) / `확인 완료`(질문에 답만 함,
코드 변경 없음). 아직 결정이 필요한 항목은 여기가 아니라 `question.md`에 모아둠.

## 레이아웃/네비게이션

1. **사이드바가 스크롤 중 안 따라옴** — `구현 완료`. `App.css`(`.app-shell`이
   `min-height: 100vh` → `height: 100vh`로, `.app-content`에 `overflow-y: auto`
   추가)와 `Layout.css`(`.sidebar`에 `min-height: 0` + `overflow-y: auto` 추가)로
   해결 — 이제 사이드바/본문이 독립적으로 스크롤되고 사이드바는 뷰포트에 고정됨.
2. **사이드바 자체 Y축 스크롤도 필요**(화면 작으면 하단 항목 접근 불가) —
   `구현 완료`. 위 수정이 이 문제도 함께 해결함(`.sidebar`의
   `overflow-y: auto` — 항목이 뷰포트보다 많으면 사이드바 안에서 스크롤됨).

## 비밀번호 게이트 확장 — `구현 완료`

**핵심 원칙 확정**: 이미 있는 `internal/authgate`(Terminal/파일 매니저가 쓰는
게이트)를 재사용해서, **읽기는 그대로 열어두고 쓰기(POST/PUT/DELETE)만 게이트**로
확장. 예외: **Logs 탭은 읽기까지 통째로 게이트**(로그 안에 시크릿이 노출될 수
있다는 사용자 판단, 읽기/쓰기 구분이 의미 없는 기능이라). Supervisor의
start/stop/restart도 쓰기 액션이라 게이트 대상. 세션 토큰 TTL도 24시간 →
10분으로 단축(사용자가 명시적으로 요청 — "계속 요구하면 쓰기 힘드니 10분짜리
토큰"이라는 표현 그대로, 매 액션마다 비밀번호를 다시 묻는 게 아니라 짧은 그레이스
윈도우).

게이트 대상 확정 목록(백엔드 에이전트에 그대로 지시):
- 게이트: supervisor start/stop/restart(POST), supervisor per-program 로그(GET),
  logs 탭 전체(GET apps/entries/range), ssh keys 추가/삭제(POST/DELETE),
  git config 쓰기(PUT/POST/DELETE 전부 — user, ssh-hosts, credentials, lfs
  install, raw 편집, signing, gpg-keys), tailscale 쓰기(PUT/POST/DELETE 전부 —
  config, forwards, publish).
- 게이트 안 함(읽기 유지): supervisor 목록(GET), ssh keys 목록(GET, "퍼블릭이니
  상관없다"는 사용자 판단), git/tailscale 전체 GET류.
- **범위 밖으로 판단해서 안 건드림**: extensions/mise 설치·삭제, projects
  스캔/rescan, dind(아직 미구현) — 사용자가 명시적으로 언급 안 함, 나중에
  필요하면 같은 패턴으로 저비용 추가 가능.

**프론트 설계(중요)**: 개별 탭마다 잠금 UI를 새로 만들지 않고, `api/client.ts`의
`request()`에 **전역 401 인터셉터**를 넣어서(어떤 API 호출이든 401을 받으면
자동으로 전역 잠금 모달을 띄우고, 성공하면 원래 요청을 자동 재시도) 이후 모든
현재/미래 게이트된 라우트가 추가 코드 없이 자동으로 동작하게 설계 — Git/Tailscale
탭처럼 "읽기는 열림, 쓰기만 잠김"인 화면은 이 인터셉터에 전적으로 의존(폼 자체를
숨기지 않음, 실제로 저장 눌렀을 때만 잠금 모달), Logs처럼 전체가 잠긴 화면은
기존 `RequiresUnlock` 래퍼를 계속 씀(탭 진입 시점에 바로 안내).

4. **PID 트리 보기**(로그 버튼 옆에 펼침 버튼 — 눌리면 해당 프로그램 PID를

## Processes

13. **프로세스 트리 보기**(어떤 프로세스가 죽으면 뭐가 같이 죽는지 보려면 트리가
    필요, ppid만으로는 사람이 보기 어려움) — `구현 완료`. 리스트 뷰와 트리 뷰
    **둘 다** 제공. 백엔드는 이미 `ppid`를 내려주고 있어서(`ProcessInfo.ppid`)
    **백엔드 변경 없이 프론트에서 트리를 구성**하는 걸로 확정(어렵지 않음으로
    판단, 마일스톤으로 미룰 필요 없음). 재사용 가능한 유틸리티로 만들어서
    Supervisor의 PID 트리 펼침 기능(위 4번)이 그대로 가져다 씀.
14. **상태(sleep/running) 필터 + 이름/커맨드 퍼지 서치 + 일치 부분 하이라이트** —
    `구현 완료`. 프론트에서 필터링(백엔드는 이미 전체 목록을 보내고 있음 —
    이 컨테이너 환경 특성상 프로세스 수가 유한/적어서 서버 필터링은 오히려
    과설계라는 사용자 판단에 동의, 백엔드 변경 없음).
15. **DOM에 한 번에 너무 많이 그려지면 랙 걸릴 수 있음 → 페이지네이션 필요**
    (가져오는 데이터 자체가 아니라 렌더링되는 DOM 개수) — `구현 완료`.
    페이지 크기 선택 가능한 클라이언트 사이드 페이지네이션.
16. **성능(cpu/mem/disk/net) 카드와 그래프가 값을 중복 표시해서 애매함, CPU는
    코어별 히트맵(작업 관리자 스타일, 호버 시 해당 코어 히스토리), 메모리는
    디스크처럼 스택형(cache/buffer 등 구성 요소별 색깔), cgroup 제한 없을 때도
    물리 메모리 총량은 표시** — `구현 완료`. 코어별 사용량(`/proc/stat`
    파싱, 코어마다 델타 샘플링)/물리 메모리 총량(`/proc/meminfo`의
    `MemTotal`)/메모리 구성요소별 분해(`MemFree`/`Buffers`/`Cached`/`Slab` 등,
    `/proc/meminfo`) 전부 stdlib만으로 가능함을 확인, 클럭 속도/온도는
    best-effort로 시도(`/sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq`,
    `/sys/class/thermal/thermal_zone*/temp`) — 컨테이너 환경에서 못 읽을 수
    있어서 기존 `available: bool` 열화 패턴 그대로 적용.
17. **Processes 탭을 "프로세스 목록"과 "성능"으로 나누는 게 좋을 듯(task
    manager/KDE system monitor처럼), 굳이 새 최상위 탭보다는 Processes 안에서
    우측 상단에 서브탭으로** — `구현 완료`. Processes 탭을 서브탭 2개
    (성능/프로세스)로 재구성, 사이드바 라벨도 "작업 관리자"류로 변경(둘 다
    포괄하는 이름 필요 — 정확한 이름은 구현 에이전트 판단에 맡김).
18. **Processes 탭이 파일에 쓰는지 확인 요청** — `확인 완료`: **아니오.**
    `internal/procinfo`(라이브 프로세스 목록)와 `internal/cgroup`(리소스
    히스토리)는 둘 다 인메모리 상태만 유지함(히스토리는 고정 크기 링 버퍼,
    프로세스 목록은 매 요청마다 새로 읽음) — 디스크에 아무것도 안 씀,
    컨테이너 재시작하면 히스토리도 그냥 날아감(이미 알려진/의도된 동작).

    --json`이 홈페이지 필드를 주는지 미확인, `.claude/extension-search-plan.md`
    1번 절 참고 — 검색/URL설치 기능과 인프라가 겹쳐서 같이 정리해둠). GitHub
    홈페이지 링크는 익스텐션 쪽도 못 만듦(API 응답에 없음).
28. **터미널 세션 관리(named 영속 세션)** — **정정: 실제로는 미착수**(이전
    기록에 "구현 진행 중"이라고 잘못 적혀 있었음 — 실제로 에이전트를 디스패치한

    살려두고 이름으로 재접속 시 재부착 + scrollback 링 버퍼로 재접속 시 유실
    방지하는 방향으로 설계 방향만 기록. `question.md`에도 착수 전 결정 필요
    항목 정리.

## 남은 것 정리

이번 라운드에 새로 디스패치된 에이전트들의 실제 구현 결과(파일 목록, 최종 API
계약, 스모크 테스트 결과)는 이 문서가 아니라 관련 `*-plan-done.md`
(`archive/supervisor-plan-done.md`, `archive/vector-logs-plan-done.md`, `qa-request/gitconfig-plan-done.md`,
`archive/tailscale-plan-done.md`, `archive/processes-plan-done.md`, `archive/terminal-plan-done.md`,
`archive/extensions-plan-done.md`, `qa-request/mise-plan-done.md`)에 완료 후 반영 예정 — 이 문서는
"뭘 하기로 했는지"의 스냅샷이고, 실제 완료 여부/세부 구현은 각 기능 문서가
최종 소스.
