# 파일 매니저 리워크 (아이디어 단계 — 구현 안 함, 최하 우선순위)

> **이 문서는 구현하지 않는다.** 사용자가 명시적으로 "일단은 논의가 필요한게
> 많다"고 밝힌 항목 — 착수 전 사용자와 스코프/우선순위를 상의부터 할 것. 지금
> 있는 파일 매니저(`.claude/archive/filemanager-plan-done.md`)는 이미 구현되어
> 정상 동작 중이며, 이 문서는 그걸 대체하자는 게 아니라 "더 편의성 있게 다시
> 짜보면 어떨까" 수준의 브레인스토밍이다. (아래 "v1에서 미뤄둔 것"은 별개로,
> 리워크와 무관하게 기존 파일 매니저 자체에 아직 안 끝난 채 남아있는 항목.)

## v1에서 미뤄둔 것 (리워크와 별개, 기존 파일 매니저 자체의 잔여 항목)

`archive/filemanager-plan-done.md` 구현 당시 "구현 시 확인할 것"으로 남겨뒀던
항목 중, 실제로 구현되지 않은 채 남은 것들 — 리워크(위 3개 편의 기능)와는
무관하지만 같은 컴포넌트라 여기 같이 적어둠:

- **업로드 진행률 표시 없음**: 지금은 스피너뿐, 브라우저 표준
  `XMLHttpRequest.upload.onprogress`로 퍼센트 표시가 가능할 것으로 추정했었으나
  실제 구현은 안 됨.
- **chmod(권한 변경) 기능 없음**: `info 패널`이 권한을 보여주기만 하고 바꾸는
  UI/API는 처음부터 v1 스코프 밖으로 판단해서 미착수.
- **디렉토리 zip 다운로드 없음**: 파일 단위 다운로드만 구현, `archive/zip`
  (stdlib)으로 구현 가능하다고 리서치는 돼 있었으나 스트리밍 중 진행률 표시가
  복잡해진다는 이유로 이번 라운드는 제외하기로 결정함.
- **실컨테이너(`docker compose build && up`) 검증 안 됨**: 로컬 스모크
  테스트(경로 탈출 차단/게이트 on-off/CRUD)는 실제 서버 프로세스로 확인했지만,
  이미지 빌드해서 컨테이너로 띄운 상태로는 아직 확인 안 함.

## 동기 (사용자 설명 그대로)

지금 파일 매니저는 업로드/다운로드/이동/복사/이름변경/멀티선택/텍스트편집/
정보패널까지는 되지만, [Termix](https://github.com/LukeGus/Termix) 같은
프로젝트를 벤치마킹하면 더 편의성 있게 만들 수 있어 보인다는 제안 — 구체적으로
언급된 편의 기능:

- 드래그 앤 드롭으로 파일 이동 (지금은 버튼 클릭으로만 이동/복사)
- 그리드/리스트/테이블 여러 뷰 모드 전환
- 여러 탭 지원 (동시에 여러 경로를 열어두고 전환)

**주의**: 이 에이전트는 Termix를 직접 열어서 확인해보지 않았다 — 사용자가
설명한 특징을 그대로 옮겨 적은 것뿐이다. 착수 시 Termix(또는 사용자가 언급한
다른 참고 프로젝트)의 실제 UI/UX를 먼저 훑어보고, 어떤 부분이 code-docker
파일 매니저에도 맞을지 판단할 것 — 통째로 베끼는 게 목표가 아니라 참고
포인트를 얻는 것.

## 왜 낮은 우선순위인가

- 사용자 본인이 "복잡하고 필수적은 아니라 진짜 낮은 우선순위"라고 명시.
- 지금 파일 매니저도 핵심 CRUD는 이미 다 됨 — 이건 순수 편의성 개선이지 기능
  공백을 메우는 게 아님.
- 그리드 뷰(썸네일?)나 다중 탭은 상태 관리 복잡도가 꽤 올라가는 리워크라
  기존 컴포넌트를 얼마나 재사용할 수 있을지부터 불확실.

## 착수 전 사용자와 논의해야 할 것 (전부 미정)

1. **범위**: 세 기능(드래그앤드롭 이동/뷰 모드 전환/멀티탭) 전부를 원하는지,
   아니면 이 중 일부만 먼저 원하는지 — 특히 드래그앤드롭 이동은 나머지 둘보다
   구현 난이도가 낮고 지금 구조에 얹기도 쉬워 보여서 먼저 떼어 갈 수도 있음.
2. **그리드 뷰의 실제 모습**: 썸네일 미리보기까지 원하는지(기존
   `archive/filemanager-plan-done.md`에서는 "썸네일 보여주고 그런건 필요 없을것
   같다"고 명시적으로 배제했었음 — 이번 요청과 상충하는지 확인 필요), 아니면
   아이콘 기반 그리드로 충분한지.
3. **멀티탭의 의미**: 브라우저 탭처럼 동시에 여러 경로를 열어두는 것인지,
   아니면 탐색기 스타일로 분할 패널(왼쪽/오른쪽 두 경로 놓고 그 사이 드래그
   이동)까지 원하는 것인지 — 후자라면 드래그앤드롭 이동 요구사항과도 자연스럽게
   묶임(두 패널 사이로 드래그).
4. **기존 게이트/경로검증 재사용 여부**: 지금 파일 매니저는 webmanager 전체에서
   가장 큰 위험 표면이라 자체 비밀번호 게이트 + `ResolvePath` 계열 엄격한
   경로검증이 이미 붙어있음(`.claude/archive/webmanager-review.md` (레포 루트)
   의 기존 관례). 리워크해도 이 부분은 반드시 그대로 유지 — 편의 기능을 얹다가
   경로검증 로직을 건드리게 되면 특히 조심.
5. **점진적 교체 vs 전면 재작성**: `src/components/FileManager/` 기존
   컴포넌트(브레드크럼, 정보 패널 등)를 얼마나 재사용할 수 있을지 코드를 먼저
   읽어보고, 뷰 모드 전환 정도는 기존 리스트 렌더링 위에 얹을 수 있을지,
   멀티탭은 상태 구조를 얼마나 갈아엎어야 하는지 가늠부터 할 것.
